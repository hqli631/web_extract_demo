# 项目二实施计划：单 Agent 驱动代码生成提取器

本轮目标：把 `web_extract_demo` 交付为“少量同布局网页 → 单 Agent 生成抽取代码 → 受限执行 → 反馈修复 → 新页面验证”的可运行项目。项目一已独立整理到 `web-body-extractor`，本仓库聚焦代码生成和反馈循环。LoRA、GRPO、多 Agent 和 RSI 历史研究材料保留作附录，不作为本轮新增任务。

## 验收口径

- 输入两三篇同布局的本地 HTML；网页内容是任务数据，不能改变系统要求。
- 生成可复用的 Python/XPath 抽取代码，输出标题、有序正文块、元数据、排除项、警告和原文位置。
- 自动执行候选并收集语法、契约、原文证据、顺序和已定义质量检查反馈；最多指定轮次修复，不无限循环。
- 生成组和开发反馈组可以进入提示；最终测试组仅在最终候选冻结后执行，测试反馈不能反向修复本轮候选。
- 保留首轮和最终代码、反馈、执行结果、调用用量与耗时，报告支持查看页面和结果。
- 模拟模型演示和真实 API 实验必须分别标注。模拟结果只能证明流程，不能写作千问真实生成效果。
- 新生成代码必须经过能力限制并在明确边界中执行；AST检查和超时不等于能运行任意恶意代码的操作系统沙箱。

## 严格执行顺序

| 工作包 | 操作 | 验收证据 |
|---|---|---|
| A：协议 | 固定任务清单、输入分组、哈希、输出字段、停止条件 | 清单可加载；角色和源码哈希可核查 |
| B：单 Agent | 实现模型适配、提示、生成、执行、反馈和有限修复 | 一条命令产生完整轨迹；失败有明确状态 |
| C：验证 | 开发回归后冻结代码，再执行隔离于反馈的测试组 | 首轮/最终对比；测试曝光状态和限制 |
| D：交付 | 可视化报告、使用说明、配置示例、失败说明 | 无密钥可运行演示；有配置可调用千问接口 |
| E：收尾 | 运行必要测试、核查凭据和范围、提交并推送 | 工程检查结果、Git提交和远程分支 |

## 确实学会的知识

1. 任务输入与生成代码的关系：输入的是有角色和来源的网页样本，不是把所有网页都交给模型当答案。
2. 工具反馈与语义反馈的区别：Python报错和XPath无证据可以自动判断，正文是否遗漏需要定义规范或可核实参考。
3. Agent修复的单位是候选代码：同一份代码修好后应复用到同布局多页，不逐网页手写答案。
4. 停止条件：达到开发检查要求或用完轮次都必须停止，失败也是有效实验结果。
5. 泛化实验：本轮提示未见不等于模型预训练从未见过；历史网页不能重新宣称为全新自然测试。
6. 成本：分别记录模型请求数、重试、token用量、执行次数和耗时；没有价格配置不伪造人民币成本。

## 停止点

当入口、有限自修复、明确边界的执行、报告和使用说明均通过验收并同步GitHub后停止。缺少API凭据或云端隔离环境时必须如实登记未实测项；不得用mock调用冒充真实千问效果。

## 本轮执行结果

A：冻结Python Insider 5页清单（2生成/1开发/2测试）及字节哈希；B：受限XPath JSON生成、可信Python模块导出与实际反馈有限修复；C：真实flash首次生成、受控漏提后的真实API修复及CPU复用；D：逐页全文报告和学习指南；E：12项新测试、全仓226项测试通过，提交并核对远程同步。详见 PROJECT2_COMPLETION.md。
