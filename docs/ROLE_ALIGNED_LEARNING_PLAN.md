# 面向离线搜索正文抽取岗位的学习与实操计划

制定日期：2026-11-12。状态：计划已制定，第三阶段尚未执行。以用户本次提供的岗位业务说明为学习依据，不把本地Demo等同于团队生产规模或内部实现。

## 1. 先回顾岗位要求，再确定主线

业务位置：离线搜索上游网页基础数据，为在线搜索、RAG等提供高质量正文。双目标是正文质量与大规模计算成本。

主力方案：按DOM/布局聚簇 → Coding Agent看簇内2—10个样本生成抽取代码 → CPU执行全簇 → 根据报错和质量反馈修复。重点难点是同簇异构、折叠内容和代码多轮修复。

研发方向：Rubrics提供可批量评价的质量信号；Agentic RL优化写代码Agent的多轮行为；RSI沉淀可复用能力、发现badcase、修补簇代码并验证。

术语更新：用户本次明确RSI按“递归自我改进”理解，后续沿用此业务定义。旧总结中的“RSI未确定”反映当时信息，不改写为已经实现。agent_io目录仍只表示输入输出，不等于agentic RL。

核心成果固定为同一个Demo：输入按布局组织的网页和少量开发样本，输出版本化的簇级抽取器、批量结果、质量证据、修复轨迹及成本报告。复用前两阶段代码，不重做标注系统或另建无关项目。

## 2. 已有基础和要补齐的能力

|岗位能力|现有基础|真实缺口|
|---|---|---|
|DOM与XPath|两类模板、原始/清理结果、固定回归|放入簇级任务，处理布局变体|
|少样本代码生成|对话AI给出XPath候选及契约检查|生成可执行解析模块，保存版本与多轮修复轨迹|
|网页聚簇|人工按站点/模板理解|结构特征分组、簇内差异检查；站点不等于布局簇|
|质量反馈|审核决定修正、漏表示例|反馈驱动抽取代码修补，而非仅改输出标签|
|Rubrics|五题与四例计分原型|代表性错例、独立抽查、judge校准|
|CPU降本|批量执行|耗时、吞吐、生成/修复/审核成本摊销|
|Agentic RL|理解计分不等于训练|策略、轨迹、GRPO；条件具备后做真实小型训练|
|RSI|历史证据与回归|badcase发现、簇级补丁、复验、回退和经验复用|

## 3. 第三阶段：主力方案Demo，固定四个单元

最高优先，先完成再进入第四阶段。每个单元都包含讲解、助手实现代码、用户运行观察和结果解释。

### 3.1 布局分组与样本协议

学习：DOM路径、标签和稳定属性、结构相似度、布局簇与站点的区别、近重复、开发/修复/测试分工。同簇存在变体，不能把不符合规则的页面全部踢掉。

操作：盘点旧样例作开发材料；目标建立两个布局簇，每簇约12篇自然页面，3篇供生成、3篇供反馈修复、6篇在抽取器冻结后最终评估。先登记分组再生成代码。自然样本不足就记录缺口，不用复制或合成页冒充独立样本。

用可解释的标签路径/结构特征与相似度做小规模分组，再检查簇内变体；不先搭大规模聚类平台。只补采完成任务必需的页面，记录来源与快照；动态页面单列风险。已暴露旧样例不当新测试页。

产物：URL、哈希、结构特征、簇ID、数据分工清单及簇报告。验收：能解释两页为何同簇、同站点为何可不同簇、哪些是自然变体。

### 3.2 少样本生成簇级抽取代码

学习：Coding Agent的输入/工具/输出协议、提示约束、函数接口、XPath与清洗逻辑、适用条件。

操作：每簇仅给生成者3篇开发页，生成独立Python模块，统一接受HTML，返回标题、有序块、元数据及定位证据。按任务保留段落、小标题、图说、表格行列。记录输入、提示、模型身份或当前对话来源、代码版本和执行结果。

先由当前对话充当Coding Agent，程序负责执行与校验；这是交互式生成和可重放执行。后续有API时再接真实调用、token及费用记录，无凭据不伪装无人值守Agent。

候选代码限制在解析接口内，独立进程设运行超时，不赋予任意网络/文件修改能力；检查语法、契约、空结果、顺序与异常，保留源快照。

产物：两个版本化候选抽取器与生成记录。验收：同簇不同文章复用代码，不按文件名或正文句子硬编码答案。

### 3.3 同簇异构、折叠正文与代码反馈修复

学习：样式分支与过拟合、结构完整性与语义质量、错误分类、折叠正文与隐藏导航的区别、修复轨迹和停止条件。

操作：用修复组暴露问题，基于执行错误和Rubrics反馈修补代码，最多2轮。每轮保存旧代码、反馈、补丁和回归差异，未修好就如实停止。

至少检查三类问题：嵌套/容器变体；信息性表格漏提；折叠正文误删。静态HTML已有的折叠正文按语义保留，隐藏菜单广告不能全留；快照根本没有的内容应报告采集/渲染缺口，不能指望XPath凭空补回。

自然badcase与合成折叠/嵌套反例分别标注，合成例只验证行为，不计自然泛化率。生成者不看封存测试页；最终测试后不能根据其结果调规则，再把同批称独立测试。

产物：代码修复轨迹与前后质量对比。验收：明确修复代码中的哪条逻辑，而非修改审核JSON凑通过。

### 3.4 CPU批量执行、成本与交付

学习：CPU时间/墙钟时间、吞吐、p50/p95、失败率、生成成本摊销、质量与成本约束。

操作：冻结代码和评分方案，执行封存页评估。对固定本地输入测批量执行，记录硬件、并发、页数、输入字节数及重复测量条件。小批次本机计时不能外推千亿级吞吐。

成本拆分：生成 + 修复 + CPU执行 + 审核。簇内N页，生成/修复支出G，每页CPU成本c，审核总支出J，则每页摊销=(G+N×c+J)/N。没有GPU或逐页模型推理实测时，仅做标明假设的成本与盈亏平衡分析，不能声称实测降本倍数。

产物：批量入口、质量/失败/成本报告、第三阶段总结、3分钟演示。验收：少样本生成代码、跨页CPU复用、至少一次有证据的代码修复、测试结论和成本边界均可演示。自然测试样本不足则标部分完成。

## 4. 第四阶段：Rubrics评价校准，固定三个单元

1. **质量规范与错例。** 复用已有五题，定义正文范围及表格、图说、折叠、元数据、unknown条件；覆盖漏段、漏表、推广混入、重复、乱序、折叠误删。不因同一错误重复扣分，不给长度本身奖励。
2. **真实评审与校准。** 分开生成与评审上下文，提供源证据和候选，保存理由及引用。小量独立抽查、重复评审，统计逐题错判/分歧、unknown率、成本和扰动响应。不逐块重标全库。无独立标注时只报告一致性/错例检查。批量API依可用账号和额度，离线重放不算新调用。
3. **reward及门槛。** 冻结计分与关键门槛，检验复制整页、堆长度、删难点等投机行为；执行错误与质量低分分开。输出评价接口、修复前后对比及第四阶段总结。

结束条件：能够区分代表性好坏结果、解释评审分歧和奖励风险、记录实际成本。未独立校准时不称稳定训练reward；不靠不断加题追求满分。

## 5. 第五阶段：Agentic RL与RSI，固定三个单元

### 5.1 多轮代码Agent与GRPO基础

用已有修复轨迹解释状态（任务/反馈）、动作（代码/工具）、环境（执行器/评审）、奖励（质量/失败/预算）。Actor是写代码的Agent，CPU解析代码是其产物。学习trajectory、policy、rollout、terminal reward、credit assignment、KL与策略更新。

GRPO实操：同任务采样多条轨迹，组内比较reward形成相对优势，再按约束更新策略。用小数组手算均值、方差、优势，解释全同分为何缺少区分信号；公式以所用框架版本为准。比较质量、修复成功率、平均迭代步数及总开销，不只追一个分数。

### 5.2 按资源开展真实小型训练

先确认GPU、可训练模型、框架、任务和reward，再定有限预算；固定训练/开发/测试划分，保存参数更新证据，比较训练前后。硬件不足则完成算法和轨迹实操，训练明确待完成；prompt重试或改规则不能冒充RL。此单元资源检查后再细化实现，不预先承诺训练效果。

### 5.3 RSI有限工程原型

复用Demo封装结构诊断、执行、评审、回归工具；批处理发现badcase，映射到簇和版本；生成候选补丁，经隔离回归与封存评估形成待采用版本，保留回退。限制修复轮数与修改范围，失败进待处理列表。

体现“发现问题—修补代码—验证—沉淀经验”的递归改进，不宣称团队规模的无人干预系统。若需制作个人Skill，届时按需要实现；一份提示文件不等于整个RSI。

结束产物：算法笔记、轨迹操作、真实训练记录或未完成说明、可复验的badcase补丁闭环、第五阶段总结。训练与工程原型分别标状态。

## 6. 带教方式、优先级与不做的扩展

- 每次先回顾岗位依据和上一步结果，标明正在执行哪个单元，不临时扩课。
- 助手写代码和配置；用户运行关键命令、观察并解释。每次提供文件路径、命令、预期结果、排查方式及操作意义。
- 单元可分多次操作，但第三阶段四单元、第四/第五阶段各三单元不变。按验收推进，不按聊天轮次或文件数量判断进度。
- 已会的XPath只结合badcase复习；不重开入门课。暂不扩展无关可视化改版、OCR精修、在线搜索或RAG应用。
- 阶段结束分别总结、更新索引；每两轮项目修改同步GitHub，保留用户旧修改。

优先级：先完成第三阶段主力业务闭环，再完成第四阶段评价；第五阶段先懂训练对象和闭环，实际训练依资源。简历只写真实样本规模、复用、修复、质量和成本结果，研究理解和计划另列。
