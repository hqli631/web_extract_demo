# 第一阶段总结：网页结构、XPath抽取与可追溯修正

归档日期：2026-11-12。状态：本阶段约定的工程功能已完成；个人掌握程度通过下方操作与解释确认。

阶段回顾索引：[LEARNING_STAGE_INDEX.md](LEARNING_STAGE_INDEX.md)。第二阶段：[STAGE2_SUMMARY.md](STAGE2_SUMMARY.md)。

## 1. 为什么做这一阶段

回顾岗位聊天记录，网页处理是任务载体：需要理解网页内容、生成可复用提取方案，并判断结果是否符合质量要求。第一阶段先建立可执行、可检查的数据处理基础，为第二阶段的任务协议、Rubrics和反馈提供原始证据。

这里处理的是保存的HTML快照。它不是网页搜索系统，也不是训练好的通用正文模型。

## 2. 已经做完的流程

保存网页与来源 → 解析DOM → 定位标题和正文容器 → 收集原始候选块 → 分类与受限修正 → 输出JSON及报告 → 与冻结基准和已保存审核记录比较。

|环节|实际完成的内容|作用|
|---|---|---|
|理解网页|观察标签、属性、父子和兄弟节点，检查正文与图说所在位置|选择容器有结构依据，而非只凭网页外观|
|执行XPath|分别使用中新网和新浪的模板规则|把一次观察转成可重复执行的规则|
|保留原始结果|保存文字、顺序、XPath及快照SHA256|修正后仍能回查修改前证据|
|字段分类|区分可读正文、小标题、图说、独立作者、来源与排除内容|避免把所有文本压成一串，也避免误删重要内容|
|受限修正|两条确认过的独立署名移入作者字段，保留访谈问题|证明“含记者字样”不等于作者署名|
|回归比较|冻结基准，检查漏图说、正常链接、风险声明、顺序等|修改一条规则后及时发现旧样例退化|
|批量展示|六篇样例统一运行，生成可读HTML与JSON|便于比较和复盘，无需逐页找输出|

项目还保留原网页区域框选、标签保存、XPath规则复用、采集及OCR候选等工程工具。这些是辅助分支；第一阶段的完成范围以六篇静态新闻样例的统一验收为准，不能据此称所有分支已达到生产质量。

## 4. 这一阶段应掌握的具体知识

|知识点|需要能解释的操作或代码|实际意义|
|---|---|---|
|解释器与路径|指定 .venv/Scripts/python.exe；区分终端工作目录与脚本路径|排除“运行了错误Python/读取错样例”的环境问题|
|编码|UTF-8文件、Python输出与PowerShell管道编码是不同环节|遇到问号时先定位编码损失，不能直接判抽取失败|
|DOM|标签、id、class、父子、后代和兄弟关系|浏览器检查功能提供结构证据，不直接提供正文语义答案|
|容器与块|先定位正文区域，再在内部收集节点|控制抽取边界，减少导航侧栏混入|
|XPath范围|./p是直接子段落，.//p是所有后代段落；开头//可能回到文档范围|扩大范围可能补漏，也可能混入嵌套推荐区|
|类名匹配|用空白边界匹配完整class词，而非任意子串|避免把pictext-extra当pictext|
|文字提取|text_content()保留内联链接文字；空白规范化会改变格式|不能因为有链接就删段落，也不能用于保真代码排版|
|非文字内容|空文本div可能含img；图说可能是单独div|空文字不等于空内容；图说提取与OCR不同|
|数据分层|原始块与清理结果分开，作者/来源单列|修正可审计，不覆盖原始证据|
|语义边界|编辑不是作者，访谈提问不是署名，风险声明仍可属于正文|不能只用关键词和字体样式决定删除|
|回归与哈希|固定baseline；SHA256识别快照变化|防止把新结果重新冻结后伪称“修复成功”|

更详细的代码解释和练习见 [PROJECT1_KNOWLEDGE_REVIEW.md](PROJECT1_KNOWLEDGE_REVIEW.md)。

## 5. 亲手回顾的操作

在VS Code的PowerShell终端执行：

~~~powershell
cd "D:\codex project\web_extract_demo"
.\.venv\Scripts\python.exe -X utf8 .\learning\run_project1.py
Start-Process ".\output\project1\index.html"
~~~

该命令会重建阶段输出和报告，并运行检查；不联网、不调用模型、不重新冻结基准。工程测试数可能随以后开发增加，回顾时以本次运行日志为准，不沿用历史测试数量。

按顺序在报告中完成三个观察：

1. 找到第二、第三篇中新网样例的原始块和作者字段，解释少掉的1个可读块去了哪里。
2. 找到新浪17块样例，确认3个小标题仍在阅读顺序中，来源单列。
3. 找到45块样例，确认正常链接和风险声明保留，说明为什么只有2块排除。

此操作的学习目标是追踪数据变换，不是重新逐条标注六篇文章。

## 7. 完成边界与对实习的帮助

已具备的项目演示能力：从静态网页结构说明容器选择，执行XPath，定位漏提或误删，保留证据并回归验证。它对应网页数据处理和质量排查的基础工作。

仍不包含：任意网站通用抽取、完整动态页面执行、图片文字可靠识别、独立大规模准确率评估、模型参数训练。代码由AI协助完成，个人能力应以能亲手运行、解释和定位问题为依据。

能够结合报告说明“为什么选这个容器、可能漏什么或混入什么、如何证明修正没有破坏旧结果”，就达到本阶段的学习验收要求。
