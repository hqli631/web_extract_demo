# 第二阶段第 1 课：准备 Agent 规则生成任务

本阶段闭环：少量样例 -> 结构化任务 -> Agent 提出候选规则 -> 程序检查 -> Rubrics 质量审核 -> 反馈修正 -> 未见验证。先用规则 JSON 限定动作，之后再学习生成 Python 代码。当前不自动聚类、不训练模型。

本课由助手准备脚本，用户运行并理解输入。执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\learning\agent_io\prepare_task.py
```

输出 `output/agent_io/task.json` 为机器可读任务，`task.md` 为阅读版。两者记录同一任务的目标、两个已知开发页、快照哈希、候选容器、子节点结构、返回格式与限制。运行不调用模型，也不会生成候选答案。

## 具体观察

1. 在 VS Code 用 Ctrl+P 打开 `output/agent_io/task.md`。
2. 看 goal：只产生原始段落 XPath，不提前执行清理。因此第一篇候选含专题导航和责任编辑，预期 45 段；第二篇预期 23 段。它们不是清理后的 43/23。
3. 看 task_id：用于对应本轮输入与 Agent 回答，避免把旧回答套到新任务。样例文件 SHA256 对应快照字节。task_id 不是模型质量分数。
4. 看候选容器：当前已经提供 artibody，不要误称 Agent 从整页自主发现正文。
5. 看 output_contract：规则、解释和局限是不同字段；只输出三个 XPath 却不说明边界，不满足本课要求。
6. 看 evidence_limits：段落预览不是全文，不能用于认定整篇语义完整。

下轮由当前对话 AI 读取任务生成 `candidate.json`，用户运行独立检查。先检查 JSON 字段、任务标识、文件哈希和 XPath 可执行性，再看结果质量。格式通过不等于正文正确。新增第三页仅作已知样例回溯，真正未见数据仍待单独建立。

关键概念：Agent 是能根据目标调用工具并观察反馈的系统；一条普通抽取脚本只是工具。I/O 是输入输出约定，不等于强化学习。Rubrics 是质量标准，评分成为 RL 奖励还需训练算法及参数更新；本阶段首先做可审计的推理与反馈迭代。
