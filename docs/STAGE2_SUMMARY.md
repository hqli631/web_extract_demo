## 1. 与岗位聊天记录如何对应

聊天记录的重点是：开放式网页任务 → 制定质量要求并写成Rubrics判断题 → 大模型根据证据回答 → 程序汇总分数 → 分数可作为反馈或奖励来源。截图明确涉及rubrics、agentic-rl、rsi。

第一阶段解决“怎样抽取和追踪错误”；第二阶段补上“怎样定义任务、审查方案、评价质量、反馈修正、判断复用条件”。项目中的agent_io只是输入输出目录名称，不等于agentic RL；RSI在岗位中的具体含义仍待确认。

## 2. 按原计划完成的四课

|课程|已经执行的内容|需要理解的知识与意义|

## 4. 后来补齐的Rubrics计分

早期R1—R6偏重块级约束与记录检查，不能完整代表岗位聊天中的整篇质量评价。补齐工作独立保留旧证据，没有改写历史评估标准，也没有增加新的课程编号。

|题目|质量要求|
|---|---|
|Q1|标题对应源文章主标题|
|Q2|主要叙述、结论与段落关键事实完整|
|Q3|信息性表格、列表和图说按约定保留|
|Q4|正文排除导航、独立推广和编辑元数据|
|Q5|已输出内容忠实、顺序正确，无杜撰、失真或重复|

分工：人定义标准；程序准备源DOM与候选输出；当前对话AI保存每题yes/no/unknown、源和输出引文及理由；程序校验响应后计算分数与采用门槛。

教学计分为yes=+1、no=-1，五题齐全且均已判定时，score=(raw+5)/10。总分至少0.9，并且关键题Q2、Q3不能为no，才进入当前静态任务的候选采用。unknown、无效引文、响应缺失或执行错误均不产生可用总分，不能通过缩小分母提高得分。

|案例|与原始候选的差异|得分|采用结论|
|---|---|---:|---|
|case_01|段落型原始正文|1.0|静态范围内候选采用|
|case_02|同页多混入一条独立APP推广，Q4=no|0.8|低于阈值|
|case_03|真实漏表输出，Q3=no|0.8|不能完整采用|
|case_04|仅在参考候选中按原位置补回表格|1.0|静态范围内候选采用|

case_04是受控参考候选，没有修复生产XPath。案例对照能说明评分响应质量变化，但不是独立评审器准确率评估。0.8不表示80%准确率，1.0不表示整页绝对正确。

## 5. 当前真正能实现什么

1. 把网页抽取任务整理成带证据、快照身份和输出契约的任务包。
2. 保存AI提供的XPath候选并执行独立程序检查，拒绝不匹配任务或提前破坏原始记录的候选。
3. 保留逐块语义审核、分类结果和结构化错误反馈，受限修改一项决定并检查其他结果。
4. 对冻结规则做已知回归、结构边界实验及新页静态DOM完整性对照。
5. 对四个固定候选重放已保存AI判断，验证引用和协议，输出逐题结果、分数、奖励信号原型及采用结论。
6. 生成HTML阅读报告和JSON证据，支持追踪“输入—候选—审核—修正—分数—采用条件”。
