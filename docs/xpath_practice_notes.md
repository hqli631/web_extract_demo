## 审核证据驱动的署名修正（2026-11-03）

- 新增 xpath_corrections.py：只执行语义审核记录中明确写出的 move_to_author 指令，不使用“出现记者就删除”的全局正则。
- 每条指令必须同时匹配原始块的 XPath、完整文本、段落类型，并且必须出现在 non_content=needs_review 的证据中；含冒号、句号或问号的文本会被拒绝，避免误删访谈问题或记者发言。
- 原始 blocks 永远保留，修正结果写入同一页的 cleaned 派生字段；作者字段保存姓名、原始署名、XPath 和原始块序号，支持追溯。
- 当前已执行的修正：第二篇第 2 块“中新网记者 薄雯雯”移入作者字段；第三篇第 3 块“中新社记者 孙翔”移入作者字段。第一篇没有独立署名。
- 前后数量：第一篇 7 -> 7 + 0 作者；第二篇 27 -> 26 + 1 作者；第三篇 34 -> 33 + 1 作者。三条“中新社记者：……”访谈问题、所有图说和“(完)”后的受访者简介均保留。
- 原始回归基准仍比较 7、27、34 块，未被清理结果替代；当时 64 项工程测试全部通过。
- 这一步完成“审核发现问题 -> 保存证据 -> 执行受限修正 -> 回归验证”闭环，不等于清理结果已经经过新一轮 AI 语义审核。
- 已新增 author_candidates.py 作为候选扫描器：只扫描短的 paragraph 署名候选，排除图片说明、带冒号的访谈问题、完整叙述句和过长段落。它只写入 author_candidates 报告字段，不会自动改正文；当前三篇样本中发现两条候选，正好对应已审核的薄雯雯和孙翔。
- 候选扫描器的定位是减少人工搜索范围，而不是替代语义判断。新模板上仍需检查候选是否真实署名，并把确认结果写入带 XPath 和完整文本的 corrections 指令。

## 单页模板迁移烟测（2026-11-03）

- 新增 xpath_transfer.py，可对隔离目录中的单个 HTML 运行当前规则，生成 JSON 和 HTML 报告，不读写开发集冻结基准。
- 报告保留源 SHA256、标题、块类型/顺序/XPath、结构质量检查，并显式标出语义审核尚未进行。
- 迁移入口会按文件名和源 SHA256 查找历史 AI 审核；命中时逐段比较历史审核正文，并强制标为回溯检查，不标成未见样本。
- 两篇同模板归档页与历史审核段落顺序及文字一致：一篇 6 段加 1 图说，另一篇 6 段；两页编辑行均未进入正文。
- 这两篇曾参与既有抽取器比较和 AI 审核，属于回溯兼容性检查；真正未见中新网页仍待采集。AI 湾隔离盲测属于另一个模板，不能代替中新网模板验证。
- 迁移报告测试验证历史页标签、段落数、图说、编辑行排除及冻结基准未改动。

## 新浪模板适配实验

- 样本：samples/blog_01.html，作为开发练习页。
- 旧规则结果：标题能找到，正文容器为 0。
- 原因：旧规则依赖中新网的 left_zw 类名，新浪使用 div#artibody。
- 第一版规则：//div[@id='artibody'] + ./p。
- 第一版结果：45 个非空文本块，混入责任编辑信息。
- 修正方法：按 article-editor 类名排除责任编辑节点。
- 第二版结果：44 个非空文本块。
- 尚待判断：首块专题链接和末尾风险声明是否纳入目标正文。
- 本次限制：只验证了这一个开发页，尚未证明适用于其他新浪文章。

## 新浪正文清理与证据保留

- 清理范围：排除专题导航、责任编辑；保留文章段落和风险声明。
- 原始结果：45 段；清理后：43 段；排除记录：2 条。
- 专题导航同时检查：整段文字来自一个直接子链接、
  文字以“专题：”开头、链接指向新浪专题路径。
- 正常正文也可能包含链接，不能根据“存在 a 标签”删除整段。
- 原始编号、文字和 XPath 保留，用于追查与修正。
- 自动检查确认：正常链接段落、风险声明及正文顺序保留。
- 当前限制：清理规则只在这个开发样本上验证，仍需跨页检查。

## 新浪字段拆分：文章来源

- 将“文章来源”从 `cleaned_blocks` 拆到独立的 `source_blocks`，没有删除原始记录。
- 当前三页结果：
  - `blog_01.html`：原始 45，正文 43，来源 0，排除 2。
  - `collected_14a028de299edfab.html`：原始 23，正文 23，来源 0，排除 0。
  - `collected_af5904c15d1deebc.html`：原始 17，正文 16，来源 1，排除 0。
- 回归检查同时验证正文、来源和排除字段，避免“分类规则已改、检查标准未改”的不一致。
- 该分类仍是当前新浪样例上的明确策略；其他网站可能使用不同来源标记，需要先观察 DOM 和文本结构。

## 新浪字段拆分：文章内小标题

- 第三篇样例第 3、10、11 段带有 `cms-style="font-L align-Center"`，且内部使用 `font` 标签。
- 根据居中样式这一 DOM 证据，将三段移入 `subheading_blocks`，不再混入普通正文段落。
- 小标题仍保留原始编号、文字和 XPath；这不是删除内容，而是细分内容类型。
- 当前只验证了一个新浪页面，其他页面必须先检查是否也使用 `align-Center`，不能直接假定。

## 新浪字段拆分：保持可读顺序

- 小标题从普通 `cleaned_blocks` 中拆出后，加入 `content_blocks`。
- `content_blocks` 按原网页顺序合并普通段落和小标题，文章来源与页面杂质不进入其中。
- 第三篇的可读内容索引仍为 1 到 16，说明分类不会破坏文章阅读顺序。
- 这体现了抽取结果的两个维度：字段分类用于分析，顺序合并用于展示和下游处理。
- 第三篇原始 17 块拆成 13 个普通段落、3 个小标题、1 个来源；可读正文仍有 16 块。
- 居中样式只是当前模板的启发式，不能独自证明标题语义；小标题记录保存样式证据。未命中居中样式也不能证明文章没有其他小标题。
- 分类回归核对编号完整分配、不重复、原文与路径未改动，以及可读内容按原始顺序合并。增加 `type` 后，检查应比较核心原文与新增类型，不能仍把新旧字典直接视为相同结构。
