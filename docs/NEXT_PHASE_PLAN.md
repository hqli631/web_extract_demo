## A．补齐候选代码检查和任务契约（5.2，首先做）

目的：先弄清模型为什么失败，避免继续增加训练步数。

任务：
1. 审计现有before/after，区分代码围栏、语法、接口、输出类型、容器定位、XPath证据问题。
2. 固定extract(bytes)和五字段契约，统一kind及metadata类别，合并已经确认的作者、原标题和图说规范。
3. 复核监督目标在完整DOM上的行为；有已知错误的代码先修正并回归，不能直接当高质量标签。
4. 建立未知模型代码的受限执行环境：无网络、非root、只读输入、无宿主凭据，限时/内存/进程。AST检查不是OS沙箱。

产物：契约版本、逐候选错误表、目标代码版本与回归结果、隔离执行入口。

验收：检查器能拒绝当前已知坏代码，接受经过复核的参考代码；候选执行必须在隔离环境。此项不要求先把小模型训练好，避免循环依赖。

你要学：语法通过≠执行成功≠正文正确；明确输出接口如何减少Agent失败。

## B．准备多布局任务并冻结新测试（5.2数据，A之后）

目的：从记住一个新浪目标转向多个布局任务；先定义评价范围再采集。

任务：
1. 先新增3个不同布局簇作为第一批，优先公开且可稳定采集的资讯、博客/访谈等；每簇至少2—3篇开发页，另留未调试的自然评估页。
2. 保存URL、时间、HTML哈希、布局依据、动态/图片缺口，进行精确及近重复排查。
3. 区分两种问题：已知布局的新文章验证跨文章复用；完全留出的布局验证跨布局生成。分别报告，不混为一个泛化率。
4. 按任务/布局及代码来源分组划分，禁止提示变体或同一目标跨集合；正式训练/开发/测试配额在采集前登记。不把新增3簇称为足够训练语料。
5. 只复核代表性边界与争议样例，AI辅助检查；不要求用户逐块标注全库。测试目标仅交评测者保管，不进入训练提示。

产物：任务清单、train/dev/test协议、来源/暴露状态、审核目标代码与覆盖矩阵。

验收：明确每种结论用哪个集合、哪些页未参与调试；所有样例可追溯。数据不足则报告规模限制，先做有限试验，不能用复制增加独立任务数。

你要学：网页数与代码生成任务数的区别；同簇异构；训练泄漏；已知布局和新布局泛化。

## C．独立校准Rubrics（补第四阶段缺口，可与B并行）

任务：
1. 使用既有Q1—Q5和正文规范，保存源证据、评审理由与引用。
2. 独立上下文不提供预期标签；选8—12个受控/自然混合例作为首批校准材料，来源类型分开记。
3. 双重审核、重复评审，记录逐题分歧、unknown和成本。用户只参与少量争议判断。
4. 验证漏表主要影响Q3、推广混入主要影响Q4；图像无法验证保持unknown；执行失败单列。
5. 检查复制整页、堆长度、删除难段等投机，冻结评分与采用门槛。

产物：校准报告、分歧清单、Rubrics/reward版本；旧复制预期答案的批次继续作废。

验收：校准中发现的问题有证据和处理规则；一致率不等于准确率，未解决的分歧如实保留。SFT不依赖reward，但正式质量声明需要可信评估；GRPO必须等此项通过。

你要学：规范、标签、评分、采用门槛与训练奖励分别承担什么作用。

## D．有限SFT和三方效果对照（5.2）

进入条件：A、B已验收；若C未完成，可跑参数更新试验，但不宣称可靠语义效果提升。

任务：
1. 先做固定提示的基座基线，再使用审核过的多任务语料短训练。先定总时限和步数上限；每次新目录，不覆盖旧证据。
2. 固定revision、tokenizer、输入、seed和解码预算；真实长度检查不静默截断。0.5B先作为基线，只有证据显示能力瓶颈时才比较更大模型，另定显存/预算。
3. 保存参数变化、optimizer step、显存、日志、adapter和重载证明。
4. 在同一冻结协议下比较参考抽取器、基座生成代码和LoRA生成代码；隔离执行、验证原文/XPath/顺序，再做语义评价。
5. 报告代码解析/契约/执行通过率、正文完整性/纯净度/结构、fail/unknown、轮数及耗时。token数不是金额，有实测账单才报费用。

产物：before/after、质量与错误表、运行/显存/预算报告、展示页。若无改善，最多按开发反馈再做一次有明确假设的对照，失败就归档，不无限调参。

验收：能够回答是否改善、改善哪类问题、代价多少；loss下降、文本变化都不能代替质量证据。新test只最终评估，曝光后改为历史测试并另冻结新集合。

你要学：过拟合、基线、变量控制、停止规则、训练信号和业务效果的区别。

## E．RSI有限修复闭环与工程交付（5.3）

依赖A—D中可用执行/评审工具。无需等待真实GRPO成功；沿用可用基座或经过审核的生成路径。

任务：批量发现badcase→映射cluster/代码版本→生成候选补丁（每案最多2轮）→隔离开发回归→通过后才做封存评估→候选采用或回滚。保留模型身份、输入、补丁、反馈和预算；失败入待处理列表。若测试失败后继续修复，该测试降级为开发材料。

产物：一次成功修复和一次拒绝/回滚演示、经验记录、版本化代码、最终报告、第五阶段独立总结。

验收：流程可回放可回退，质量和成本可解释。产出3分钟演示、README与简历事实表；不称为无人干预生产系统。

你要学：RSI能力沉淀、质量门禁、版本/回滚、线上badcase闭环思路。

## F．真实Agentic RL/GRPO（5.2进阶，条件项）

进入条件：C的可信reward、多任务数据、隔离执行、训练框架及单卡rollout内存预算均已核验。现有一次SFT不满足这些条件。

任务：同任务真实多候选轨迹→执行与reward→组内优势/clip/KL→Actor更新。先做有限rollout预检，再做极小更新，记录参数、采样/审核/训练开销及质量/轮数。资源不符则保留算法理解和轨迹产物，真实GRPO标待完成；不强行购买算力。

产物/验收：可追溯rollout与更新证据、固定测试对照；旧历史修复不能冒充当前策略采样。全同分缺乏有效区分信号要如实记录。

执行顺序：A→B；C可并行→D→E形成工程交付；F按条件作为进阶实验，可在E前后安排。避免为了先训练GRPO而拖延主项目交付。

单元指一次有明确输入、产物和验收的集中实操，不保证等于一轮聊天或一天。A—E是下一轮工程交付边界；工作量估算约6—11个集中单元（C可并行），受采集与用户反馈影响，不能承诺一天完成。F不计入基本交付时间，也不承诺质量必然提升。
