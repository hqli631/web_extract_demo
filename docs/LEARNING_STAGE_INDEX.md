## 推荐阅读顺序

1. 先读第一阶段总结，弄清输入、原始块、清理结果、元数据和基准的关系。
2. 再读第二阶段总结，区分任务验证、质量判断、计分、采用门槛和模型训练。
3. 每阶段各运行统一入口，对照报告回答总结中的验收问题。
4. 对某个知识点不理解时再进入详细文档，不必重做所有历史实验。

## 后续阶段的固定归档约定

每个阶段完成时，由助手主动在docs中新增独立的STAGE编号_SUMMARY.md并更新本索引、README导航。已归档阶段记录保留；后续结果变化用有日期的补充说明，不静默改写历史评估。

每份总结必须包含：

1. 回顾岗位聊天记录：本阶段对应的要求、目标与明确边界。
2. 原定计划与实际进程：哪些完成、哪些未完成、是否存在有理由的调整。
3. 当前可实现功能：输入、处理过程、输出和适用条件。
4. 具体知识点：关键表达式或协议、操作方式，以及为什么这样做。
5. 可执行复习命令：前置条件、打开路径、预期结果及是否联网/调用模型/改写文件。
6. 结果与失败证据：区分开发页、未见评估、受控反例；分数和测试通过不包装成准确率。
7. 核心文件导航：配置、脚本、证据和报告分别负责什么。
8. 用户学习验收与下一阶段交接：需要能解释什么、还有哪些能力边界；不自动扩展任务。

若阶段未达原定结束条件，标为进行中或部分完成，不为赶进度宣称完成。工程完成、用户掌握和生产可靠性分别记录。
