## 2. 先看同页混入推广：为什么扣分

case_01与case_02使用同一网页。第二个候选只多了一条“海量资讯、精准解读，尽在新浪财经APP”的独立组件文案。文章自身产品介绍保留不变。

打开case_02的Q4，可看到源s104推广组件和输出injected_widget证据，判断为no。其他四题yes：段落未删、题目正确、源中无表格等任务结构缺失、已输出事实没有被改写。多出的真实组件主要在纯净度Q4扣分，不重复称为事实杜撰。

算分：4×(+1)+1×(-1)=3；(3+5)/10=0.8。相比全yes的原始5分/1.0下降0.2。复制更长的网页不一定更好，混入页面组件会损害纯净度。

## 3. 再看漏表：同样0.8，为什么不能完整采用

case_03沿用真实 ./p 输出。源s012是一张5行3列的APP比较表；输出从o011分节标题直接接o012表注，因此Q3=no。Q2主评叙述段落，这些段落都在，避免同一漏表被两题重复扣分。

Q3是提前约定的关键质量门槛，即使其他题合计0.8，也不得作为完整文章采用。Q2同样是关键门槛；另外总分须≥0.9才可进入当前静态任务的候选采用。不是把0.8称为80%准确率。

case_04仅在同页参考候选中把源表格按行列和原位置补回，没有改生产规则。Q3变yes，恢复1.0。这展示模型判断对内容变化的响应，不是新页盲测或全面评审器校准。

## 4. 看unknown与无效证据为何没有总分

报告末尾提供两次程序实验：一项判断为unknown时，score和reward_signal为null；伪造证据引文时，返回协议错误，分数也为null。

unknown表示证据不足，不是no；无效响应表示不能信任评审结果，也不是正文质量差。不能只对剩余题算平均分，否则缺失证据反而可能让分数变高。

## 5. 打开三个文件，理解系统分工

|文件|是谁负责什么|
|---|---|
|config/body_quality_rubric.json|人确定质量要求；本项目由助手提出并说明假设，固定题目、方向、评分、门槛|
|output/agent_io/quality_score/task.json|程序从源DOM取完整证据，并提供四个待评候选；源和输出分开，记录任务哈希|
|output/agent_io/quality_score/model_response.json|当前对话AI给出逐题yes/no/unknown、源/输出引文和理由；不返回总分|
|output/agent_io/quality_score/results.json|程序校验题目、返回完整性、引文位置及原文，再确定性计分与执行门槛|

引文合法只证明引用存在，不能证明语义判断合理或覆盖完整。模型可能错；应通过小量独立人工审查校准，检查不同网页类型、评审一致性与错误样例。人工抽查用于改进评审标准，不是替代训练期间逐次自动评价。

## 6. 与reward、agentic RL的关系

当前reward_signal等于归一化质量分，名称表示可以作为奖励的候选信号，尚未校准为训练reward。实际使用还要验证指标是否鼓励错误行为、奖励如何分配、评审成本与稳定性。

本次没有策略采样、训练优化器、梯度或参数更新。训练系统将任务交给Agent采样行为，执行后调用自动评审器获得reward，再由算法更新策略，这是另一个工程环节。当前完成了其中的“基于Rubrics的质量评审与计分原型”。

评分风险：等权并非业务最优；题目可能相关；模型可能偏好长文；复制整页可能增加覆盖却夹杂广告；只看容器内可能漏容器外内容；同一对话生成和审核存在偏差。本轮公开这些限制，不包装为独立盲评。

静态任务不包含动态页面与图片文字核验。若产品要求整页可见正文，应补证据再判，不能把当前静态范围的1.0当完整网页的绝对质量。
