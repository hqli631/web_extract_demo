## 2. 在报告观察局部漏提

找到 nested_one，展开实际文字。缺少源文章首段，实际第一块从源文章第二段开始。

修改前结构：

~~~html
<div id="artibody">
  <p>第一段</p>
  <p>第二段</p>
</div>
~~~

受控变换后：

~~~html
<div id="artibody">
  <div class="experiment-wrapper"><p>第一段</p></div>
  <p>第二段</p>
</div>
~~~

./p 只选直接子 p，第一段变成后代但不再是直接子节点，因此被漏掉。结果仍有22段，所以“容器唯一、结果非空”都不能证明内容完整。

23是变换前已知参照，不是检查器凭空知道所有真实页面应有多少段。真实新网页需要独立参考或完整性审核。合成实验只能证明程序在明确变换下的行为。

## 3. 理解 empty_blocks

nested_all 给全部 p 包一层 div 后，原始文字完全保留，旧 ./p 却返回0。empty_blocks 表示块选择为空，不代表网页没有文字。

与 other_template / renamed_container 比较：后两者首先找不到容器，失败发生得更早。报告同时保留标题数、容器数、段落数，主状态优先报告容器异常，便于定位。

容器问题 -> 先看模板/路由；块定位问题 -> 看 ./p、嵌套、图说等；已提取块的去留问题 -> 看 Rubrics 和审核。不同错误不要混在一起修改。

不要立即把 ./p 全局改为 .//p：扩大范围可能把容器内部推荐、广告或组件里的 p 也收进来。此问题记录为后续建议，本阶段不追加优化课程。

## 4. 打开冻结配置，理解实验可重复性

用 Ctrl+P 打开 config/agent_eval_batch.json，观察：

- frozen_files：候选、Rubrics、实验代码和原始快照的 SHA256。
- cases：每项的 role、source、变换方式、参照数、预期状态。
- limits：哪些结论本实验不能证明。

脚本只核对冻结记录，不自动改哈希。输入变化会中止，以免拿“新规则”冒充原实验。本轮创建配置后才运行评估；这是受控实验版本冻结，不是对合成题目进行盲测。冻结哈希也不是签名认证。

为兼容 Git 在 Windows 的换行转换，代码和 JSON 配置按 LF 规范化后计算哈希；HTML 原始快照仍按字节计算。

在内存构造变体，不改 samples 源文件，不额外复制多个HTML。原网页链接指向源快照，不是变体。真实页面按字节哈希去重；这不能取代按规范化URL、正文近重复去重。

## 5. 学会解释三种样例用途

|用途|什么时候使用|看过结果后怎么办|
|---|---|---|
|开发样例|生成规则、调试Rubrics、分析错误|继续用于开发，不用于宣称未见效果|
|回归样例|固定已确认期望，防止新修改破坏旧能力|保留快照和参照，变更需解释|
|未见评估样例|规则/标准固定后，对新页面做独立评估|一旦用于调试，记录已暴露，另建新评估批次|
