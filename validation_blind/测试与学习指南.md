# 冻结验证：测试与学习指南

本流程用于检查未参与规则调整的页面，不自动训练模型。当前提取器仍以 DOM、正文范围和规则为主；AI 审核记录提供参考答案，不代表人工真值。

## 直接运行

在 VS Code 的 PowerShell 终端执行：

```powershell
cd 'D:\codex project\web_extract_demo'
$env:PYTHONPATH='.deps'
$env:PYTHONIOENCODING='utf-8'
& 'C:\Users\35516\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' run_blind_validation.py
Start-Process '.\validation_blind\reports\progress.html'
```

这个命令读取已有快照并重新生成报告，不需要重新下载网页。需要按白名单低量采集时，在 Python 命令末尾加 --collect。

## 看哪些文件

- reports/progress.html：逐页展示来源、抽取正文和审核状态。
- reports/pending_review.json：结构化结果及漏段、额外段落、杂质检查。
- reports/ai_review.json：当前对话 AI 对照原页面所作的审核，绑定快照哈希。
- reports/collection_manifest.json：采集地址、时间、文本哈希和快照哈希。
- evaluation_context.json：被冻结的提取代码哈希。
- samples/：用于复现的 HTML 快照。

## 状态含义

- pass：抽取段落与该快照的 AI 审核记录逐段、顺序一致，且未命中记录中的排除文本。
- fail：存在漏段、多余段落、顺序差异或杂质，需要检查差异。
- pending_ai_review：没有该快照的审核记录，不能当作正确样本。
- stale：快照变化，旧审核失效。
- development_overlap：URL、文本哈希或 HTML 快照与已登记开发样本重复，排除出独立验证。URL 判重忽略查询参数，采取保守排除；不同查询参数代表不同文章的站点可能因此多排除一些页面。

去重覆盖主 samples、新闻开发 samples 和两处采集清单，不能证明覆盖所有历史外部数据。

## 当前结果与后续顺序

当前保存两页：头条一页经 AI 审核通过；中新网一页因开发集重叠被排除。新浪 K 的 robots 获取/连接失败而被保守跳过，不能据此说网站明确禁止采集。

1. 先运行报告，学习一次原始 DOM → 正文范围 → 段落 → 审核差异的数据流。重点阅读 run_blind_validation.py 的 audit_page 和 development_overlap。
2. 采集新的、获准访问的文章；确认不是开发集重复，再由 AI 对照原文审核。优先补不同站点、长文、多小标题和论坛主帖。
3. 根据审核发现的问题再改规则，把失败样本加入开发回归；它以后不能继续算独立验证。
4. 修改提取代码后使用 --batch validation_blind_round2 创建新批次，并采集新的未参与修改的页面。旧审核不自动迁移。
5. 运行 python -m unittest discover -s tests 检查功能回归。测试通过说明已覆盖行为正常，不等于真实网页准确率。

先建立跨站、不同结构的有效验证样本，再讨论扩大采集量或接入训练。不要用提取器自己的输出直接生成参考答案。
